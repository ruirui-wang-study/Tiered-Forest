## 🔬 实验一: 核心消融实验 (Ablation Study)

### **实验组设计**

基于现有的`experiment_v2/models.py`结构,设计以下8个实验组:

| 实验组ID | 名称 | Tier 1<br>(Symbolic) | Tier 2<br>(Semantic) | Tier 3<br>(LLM) | 动态阈值 | 目的 |
|---------|------|---------------------|---------------------|----------------|---------|------|
| **E0** | Full System | ✓ | Cross-Encoder | DeepSeek | ✓ | 完整系统基线 |
| **A1** | No-Tier1 | ✗ | Cross-Encoder | DeepSeek | ✓ | 验证Tier 1的价值 |
| **A2** | No-Tier2 | ✓ | ✗ (直接送LLM) | DeepSeek | ✗ | 验证Tier 2的价值 |
| **A3** | No-Dynamic | ✓ | Cross-Encoder | DeepSeek | ✗ | 验证动态阈值的价值 |
| **A4** | Two-Tier-Only | ✗ | Cross-Encoder | DeepSeek | ✓ | 证明三级优于二级 |
| **A5** | Tier1+LLM | ✓ | ✗ | DeepSeek | ✗ | 跳过Tier 2直接LLM |
| **A6** | Single-Threshold | ✓ | Cross-Encoder | DeepSeek | ✗ | 单阈值vs双阈值 |
| **A7** | Aggressive-Pass | ✓ | Cross-Encoder | DeepSeek | ✗ | 激进Fast-Pass策略 |

### **实现细节**

#### **E0: Full System (完整Tiered-Forest)**

```
架构流程:
  1. Tier 1 Symbolic: 规则过滤 (零成本)
     - 检查缓存/规则匹配
     - 如果命中 → 直接返回
  
  2. Tier 2 Semantic: Cross-Encoder评分
     - 调用Small Model生成候选答案
     - 用Cross-Encoder对(Question, Draft)打分
     - 动态阈值: τ_high(t) = f(负载, 预算)
     
  3. 路由决策:
     - score > τ_high → Fast-Pass (返回Draft)
     - score < τ_low → Discard或送LLM兜底
     - τ_low ≤ score ≤ τ_high → 送Tier 3
     
  4. Tier 3 LLM: DeepSeek推理
     - 深度CoT推理
     - 返回最终答案

参数配置:
  - τ_low = 0.2 (基础)
  - τ_high = 0.7 (基础)
  - 动态调整: λ₁=0.1, λ₂=0.15
```

#### **A1: No-Tier1 (移除符号层)**

```
架构流程:
  1. 跳过Tier 1 → 直接进入Tier 2
  2. 所有候选路径都需要Small Model评分
  3. 其余同E0

预期结果:
  - Token消耗增加: +20-30% (Small Model调用增多)
  - 延迟增加: +10-15% (失去零成本过滤)
  - 准确率: 基本持平 (Tier 1主要影响效率)

验证点:
  - 如果Token增加显著 → 证明Tier 1有效减少下游负载
  - 如果准确率下降 → 说明规则过滤也有质量贡献
```

#### **A2: No-Tier2 (移除语义层)**

```
架构流程:
  1. Tier 1 Symbolic过滤
  2. 未命中规则的 → 直接送Tier 3 LLM
  3. 跳过Cross-Encoder评分

预期结果:
  - Token消耗暴增: +200-400% (所有问题都调用LLM)
  - 准确率: 可能略微提升 (LLM处理所有问题)
  - 成本效率: 大幅下降

验证点:
  - 如果Token暴增但准确率提升有限 → 证明Tier 2的成本-效益优势
  - 这是"为什么需要中间层"的核心证据
```

#### **A3: No-Dynamic (静态阈值)**

```
架构流程:
  - 完整三级架构
  - 但τ_high和τ_low固定不变
  - 不响应系统负载和预算变化

参数配置:
  - τ_low = 0.2 (固定)
  - τ_high = 0.7 (固定)

预期结果:
  - 在稳定负载下: 与E0性能接近
  - 在负载波动场景: 成本控制能力下降

验证点:
  - 需要模拟负载变化场景(高峰/低谷)
  - 观察动态阈值是否能平滑成本曲线
```

#### **A4: Two-Tier-Only (二级级联)**

```
架构流程:
  1. 跳过Tier 1
  2. Tier 2 Cross-Encoder评分
  3. Tier 3 LLM验证

对比意义:
  - 这是"FrugalGPT + Cross-Encoder"的等价配置
  - 证明"三级优于二级"

预期结果:
  - 比E0多消耗20-30% Token (缺少Tier 1过滤)
  - 准确率持平
```

#### **A5: Tier1+LLM (跳过Tier 2)**

```
架构流程:
  1. Tier 1 Symbolic过滤
  2. 未命中 → 直接Tier 3 LLM
  3. 跳过Tier 2语义评分

对比意义:
  - 测试"是否一定需要中间层"
  - 如果Tier 1召回率高,是否可以直接LLM

预期结果:
  - Token消耗: 比E0高150-200%
  - 准确率: 可能略高 (LLM处理更多)
  - 但成本效率远低于E0
```

#### **A6: Single-Threshold (单阈值模式)**

```
架构流程:
  - 只有一个阈值τ
  - score > τ → Fast-Pass
  - score ≤ τ → 送LLM
  - 没有"Discard"机制

参数配置:
  - τ = 0.5 (中等)

对比意义:
  - 验证"双阈值(模糊区)"的必要性
  - 单阈值是传统级联的标准做法

预期结果:
  - 无法丢弃低分路径 → LLM调用增多
  - Token消耗: +30-50%
```

#### **A7: Aggressive-Pass (激进Fast-Pass)**

```
架构流程:
  - 完整三级架构
  - 但τ_high降低至0.5 (更容易Fast-Pass)
  - τ_low保持0.2

参数配置:
  - τ_low = 0.2
  - τ_high = 0.5 (降低)

对比意义:
  - 测试"过度追求成本节省"的风险
  - 观察准确率-成本的权衡边界

预期结果:
  - Token消耗: -40-50% (大量Fast-Pass)
  - 准确率: 下降5-10% (误判增多)
```

## 🎯 实验二: 公平基线对比 (Fair Baseline Comparison)

### **问题陈述**

原论文对比中,FrugalGPT使用LLaMA-7B,而Tiered-Forest使用Cross-Encoder,这在组件选型上不公平。需要设计公平对比实验,分离"架构贡献"与"组件贡献"。

### **公平对比方案**

| 基线ID | 名称 | 架构 | Tier 2模型 | 说明 |
|--------|------|------|-----------|------|
| **B0** | Standard ToG | 单级(LLM全验证) | ✗ | 原始基线 |
| **B1** | FrugalGPT-Original | 二级级联 | LLaMA-7B | 原论文配置 |
| **B2** | FrugalGPT-Fair | 二级级联 | Cross-Encoder | **公平对比** |
| **B3** | FrugalGPT-SBERT | 二级级联 | SBERT | 另一种轻量模型 |
| **B4** | Tiered-Forest | 三级级联 | Cross-Encoder | 本文方法 |
| **B5** | Tiered-Forest-LLaMA | 三级级联 | LLaMA-7B | 反向验证 |
| **B6** | Tiered-Forest-SBERT | 三级级联 | SBERT | 组件替换 |
| **B7** | Tiered-Forest-Jaccard | 三级级联 | Jaccard | 最轻量配置 |

### **实现细节**

#### **B2: FrugalGPT-Fair (公平版FrugalGPT)**

```
架构设计:
  Stage 1: Cross-Encoder评分
    - 生成候选答案(用Small Model)
    - 用Cross-Encoder打分
    - 单阈值: τ = 0.6
    
  Stage 2: DeepSeek LLM
    - score < 0.6 → 送LLM重新推理

关键点:
  - 与Tiered-Forest使用相同的Cross-Encoder
  - 但只有二级架构(无Tier 1)
  - 单阈值策略(无模糊区)

对比维度:
  - 如果B2 vs B4性能接近 → 说明Tier 1贡献有限
  - 如果B4显著优于B2 → 证明三级架构的优势
```

#### **B5: Tiered-Forest-LLaMA (反向验证)**

```
架构设计:
  - 完整三级架构
  - 但Tier 2使用LLaMA-7B替代Cross-Encoder
  
实现方式:
  1. Tier 1 Symbolic过滤
  2. Tier 2: 调用LLaMA-7B生成答案并自评分
     - Prompt: "Answer and rate your confidence (0-1): {question}"
     - 解析输出获取confidence score
  3. Tier 3: DeepSeek验证

对比意义:
  - 如果B5性能接近B4 → 说明架构比组件更重要
  - 如果B5显著弱于B4 → 说明Cross-Encoder的专用性优势
```

#### **B7: Tiered-Forest-Jaccard (最轻量配置)**

```
架构设计:
  - 完整三级架构
  - Tier 2使用Jaccard相似度(零参数)
  
实现方式:
  1. Tier 1 Symbolic过滤
  2. Tier 2: Jaccard评分
     - 计算Question与候选路径的词重叠
     - score = |Q ∩ Path| / |Q ∪ Path|
  3. Tier 3: DeepSeek验证

对比意义:
  - 验证架构在"极简组件"下的鲁棒性
  - 对应real_world_experiment.md中的实际场景
```

## 📊 实验三: 参数敏感性分析 (Hyperparameter Sensitivity)

### **3.1 阈值网格搜索**

```
实验矩阵:
  τ_low  ∈ {0.1, 0.15, 0.2, 0.25, 0.3}
  τ_high ∈ {0.5, 0.6, 0.7, 0.8, 0.9}
  约束: τ_high > τ_low + 0.2 (确保模糊区存在)

总实验组数: 5 × 5 = 25组

评估指标:
  - 准确率 (Accuracy)
  - Token消耗 (Total Tokens)
  - 成本效率 (F1-Score / Cost)
  - Fast-Pass率 (%)
  - LLM调用率 (%)

可视化:
  - 热力图: τ_low × τ_high → Accuracy
  - 热力图: τ_low × τ_high → Token Cost
  - 散点图: Accuracy vs Token (Pareto前沿)
```

### **3.2 动态阈值参数搜索**

```
实验矩阵:
  λ₁ ∈ {0.05, 0.1, 0.15, 0.2}  (负载响应系数)
  λ₂ ∈ {0.1, 0.15, 0.2, 0.25}  (预算控制系数)
  τ_base ∈ {0.3, 0.4, 0.5}     (基础阈值)

总实验组数: 4 × 4 × 3 = 48组

模拟场景:
  - 稳态负载: 恒定QPS
  - 峰值负载: QPS突增2倍
  - 预算紧张: 成本限制减半

评估指标:
  - 准确率方差 (稳定性)
  - 成本超支率 (预算控制)
  - 阈值振荡频率 (系统稳定性)
```

### **3.3 跨数据集阈值迁移**

```
实验流程:
  1. 在MetaQA上学习最优阈值 (τ_low*, τ_high*)
  2. 将(τ_low*, τ_high*)应用到WebQSP
  3. 在WebQSP上学习最优阈值
  4. 将其应用到Logistics
  5. 学习"通用阈值"(在混合数据集上优化)

评估指标:
  - 迁移性能下降幅度: Δ Accuracy
  - 通用阈值 vs 专用阈值的差距
  
结论:
  - 如果迁移损失<5% → 模糊区概念具有普适性
  - 如果迁移损失>15% → 需要领域自适应
```

## 📈 实验五: 召回率与误杀分析 (Recall & False Negative Analysis)

### **实验目的**

解决"Tier 1召回率瓶颈"问题(待改进2 第5-14行)

### **实验设计**

#### **5.1 Tier 1召回率监控**

```
数据收集:
  对于每个问题,记录:
    - Tier 1是否命中规则
    - 如果命中,答案是否正确
    - 如果未命中,最终答案是否正确
    - 正确答案是否在Tier 1丢弃的路径中

计算指标:
  - Tier 1召回率 = (Tier 1保留的正确路径) / (所有正确路径)
  - Tier 1误杀率 = (Tier 1丢弃的正确路径) / (所有正确路径)
  - Tier 1精确率 = (Tier 1保留的正确路径) / (Tier 1保留的所有路径)

阈值设置:
  - 召回率 > 95% → 安全
  - 召回率 85-95% → 警告
  - 召回率 < 85% → 危险(需要回溯机制)
```

#### **5.2 规则严格度实验**

```
实验组:
  - Strict Rules: 严格Schema约束
  - Moderate Rules: 允许1-hop偏差
  - Loose Rules: 只过滤明显错误
  - No Rules: 跳过Tier 1

对比维度:
  - 召回率 vs 过滤率
  - 准确率 vs Token消耗

目标:
  找到"召回率-效率"的最佳平衡点
```

## 🎯 实验六: 问题类型分层分析 (Question Type Stratification)

### **实验目的**

解决"路径独立性假设缺陷"问题(待改进2 第16-28行)

### **实验设计**

将数据集按问题类型分层:

| 问题类型 | 定义 | 示例 | 预期最优策略 |
|---------|------|------|------------|
| **事实型** | 单跳查询 | "Who created Linux?" | Tier 2高置信度Fast-Pass |
| **比较型** | 需要比较 | "Who is taller, A or B?" | 需要Global Reranker |
| **聚合型** | 需要计数/求和 | "How many movies did X direct?" | 收集多路径 |
| **推理型** | 多跳推理 | "What did X's founder also create?" | LLM深度推理 |
| **布尔型** | 是/否判断 | "Is X a director?" | 高阈值Fast-Pass |

### **分析维度**

```
对于每种问题类型:
  1. 统计各Tier的处理分布
     - 事实型: 80%在Tier 1/2解决
     - 推理型: 60%需要Tier 3
     
  2. 计算类型特定的最优阈值
     - 事实型: τ_high = 0.8
     - 比较型: τ_high = 0.5 (更多送LLM)
     
  3. 识别架构短板
     - 比较型准确率下降 → 需要Global Reranker
```

### **核心指标**

```python
实验记录结构:

  # 延迟指标
  "latency_avg": 1.2,

  "latency_p95": 2.5,
  "latency_breakdown": {
    "tier1": 0.01,

  },
  
  # 路由统计

  "tier2_discard_rate": 0.20,

  # 召回率分析

  "tier1_precision": 0.85,
  
  # 阈值信息

  "tau_high": 0.7,
  "dynamic_enabled": true,
  "tau_adjustments": 12  # 动态调整次数
```

### **对比指标**

```
成本效率指标:
  - Token节省率 = (Baseline_Tokens - Method_Tokens) / Baseline_Tokens
  - 成本-准确率比 = Accuracy / Cost
  - Pareto效率 = 是否在Pareto前沿上

架构贡献指标:
  - 架构增益 = (三级架构 - 二级架构) / 二级架构
  - 组件增益 = (高级组件 - 基础组件) / 基础组件
  - 协同效应 = 总增益 - 架构增益 - 组件增益

稳定性指标:
  - 准确率标准差 (跨数据集)
  - Token消耗变异系数
  - 阈值振荡频率
```
