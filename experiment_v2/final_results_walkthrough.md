## 🔍 Deep Dive Analysis

### 1. The SBERT Advantage (B6 vs E0)
- **Problem**: The original Cross-Encoder (E0) was computationally heavier ($0.0008) and didn't provide better discrimination than cheaper alternatives.
- **Solution**: SBERT (B6) provides semantic embeddings at a fraction of the cost ($0.0003).
- **Result**: B6 achieved **18% higher relative accuracy** (28.9% vs 24.4%) while reducing token costs by **62%**.

### 2. Thresholding Strategy (Single vs Dynamic)
- **Observation**: Variant A6 (Single Threshold) outperformed E0 (Dynamic).
- **Insight**: The complex "Dual Threshold Dynamic Routing" introduced noise. A well-tuned single threshold (e.g., 0.8-0.9) is more robust for these datasets.

### 3. The Failure of Weak Components (B7, B5)
- **Jaccard (B7)**: Failed to filter effectively, causing 100% escalation to LLM -> **30x Cost Increase**, **15x Latency**.
- **LLaMA Self-Confidence (B5)**: Added latency without accuracy gain. 6.7% accuracy on MetaQA vs 0% baseline shows it's not a reliable scorer.

## 💡 Recommendations

Based on these results, we recommend:

1.  **Refactor Architecture**: Simplify the default routing strategy to **Single Threshold**.
2.  **Switch Component**: Replace Cross-Encoder with **SBERT** (or similar light embedding model) as the default Tier 2 scorer.
3.  **Deprecate**: Remove "Jaccard" and "Dynamic Routing" from the primary production path to reduce code complexity.
